# AI asset assistant

Available in v0.60.0. In Chat choose **AI assistant**, pick a configured OpenAI,
Claude or Gemini connection and model, and enable external AI access in Settings.
Then write ordinarily:

- "I own a Makita drill, model DHP484, serial 0012345. Its battery type is 18V LXT."
- "My F150's tire size is 205/55R16 and its paint is Oxford White."
- "What color is my bicycle?"

The model chooses among a small set of tools: search your current assets, read
one asset's current details, add one owned asset, save several details on one
asset, ask you a question, or answer. LifeGather validates and performs every
write; the model never sees an account ID, database query or unrestricted tool.
**Local assistant (no AI)** keeps the existing offline commands and never
contacts a provider.

## What is checked before saving

- Each value, name, manufacturer, model and serial must appear in your own words
  (this message or the earlier message a pending question came from). Invented,
  normalized or looked-up values are refused and nothing is saved.
- Adding an item needs your own words stating current ownership. Model and serial
  need a manufacturer. Possible duplicates produce a choice; only your answer to
  that question can add a separate item or link to a listed existing one.
- All details in one request are saved together or not at all. Several current
  statements for the same detail, or a record that changed after it was read,
  stop the request with an explanation.
- Asset IDs must come from this request's searches/reads, the selected record or
  the pending question. Another account's records are never readable.
- One write per request, at most 6 model replies and 8 reads, bounded context.

The reply after a save is generated by LifeGather from the committed result, with
**Open** and source links; the model cannot claim a save that did not happen.
Questions and answers always say when nothing was saved.

## Evidence and history

Your message is saved as the source for every detail, and asset entries record
the provider/model and your ownership words. Change history shows the method
**ai assistant**. Updated details keep their earlier statements as history.
Replaying the same request returns the stored outcome without another model call.
Stopping a request before its write commits prevents the write.

## Progress while it works

Since v0.61.0 Chat shows short progress lines while an assistant request runs, such
as "Searching your assets…" or "Checking details before saving…". LifeGather
writes these itself at each tool-loop stage; they never contain model text or
reasoning and never claim that anything was saved. The reply, and any saved
result, appears only once the request's turn is committed. Stopping, retrying and
replaying behave as before.

## Pending questions

A question the assistant asks is saved with the turn. Only your next message in
the same conversation can answer it; a new conversation, a later question, a
refused write or a changed record ends it.

## Limits

- One physical asset per request; no batch entry, deletion, merging, or asset
  type assignment/typed template fields yet (use the asset page for those).
- Home/place profiles are not edited by the AI assistant.
- Ask AI remains the cited evidence-recall mode; assistant answers about records
  use only the details it read in that request.
- Synthetic scripted-provider tests cover the tool loop. Real model quality has
  not been verified against live providers.
